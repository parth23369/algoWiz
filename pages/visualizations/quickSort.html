Quick Sort Code

function quickSort(arr, low = 0, high = arr.length - 1) {
  if (low < high) {
    let pi = partition(arr, low, high);

    // sort left part
    quickSort(arr, low, pi - 1);

    // sort right part
    quickSort(arr, pi + 1, high);
  }
  return arr;
}

function partition(arr, low, high) {
  let pivot = arr[high];   // choose last element as pivot
  let i = low - 1;

  for (let j = low; j < high; j++) {
    // if current element < pivot
    if (arr[j] < pivot) {
      i++;
      // swap arr[i] and arr[j]
      [arr[i], arr[j]] = [arr[j], arr[i]];
    }
  }

  // place pivot in correct position
  [arr[i + 1], arr[high]] = [arr[high], arr[i + 1]];

  return i + 1;
}

Quick Sort is a divide-and-conquer algorithm that works by selecting a "pivot" element from the array and partitioning the other elements into two sub-arrays according to whether they are less than or greater than the pivot. The sub-arrays are then recursively sorted.

Step by step

  • Choose a pivot as the last element.
  • Partition the array so that elements less than the pivot come before it, and elements greater come after it.
  • Recursively apply the above steps to the sub-arrays of elements less than and greater than the pivot.
  • Base case: arrays of size 0 or 1 are already sorted.

Complexity

Average and best case: O(n log n) — when the pivot divides the array into two equal halves
Worst case: O(n²) — when the smallest or largest element is always chosen as the pivot (e.g., already sorted array either in ascending or descending order) Space complexity: O(log n) on average due to recursive stack space, O(n) in worst case Stable: No (equal elements may not maintain their original order)

When is it used?

Quick Sort is widely used in practice due to its efficiency and in-place sorting capability. It's often the default sorting algorithm in many programming languages' standard libraries (e.g., Java's Arrays.sort for primitives). However, it may not be the best choice for small arrays or when stability is required. Thus it is used as hybrid with other algorithms like Insertion Sort for small sub-arrays, and Merge Sort when stability is needed while Quick Sort handles the large sub-arrays.

Compared to other sorts

  • Merge Sort: Merge Sort is stable and has a guaranteed O(n log n) time complexity, but it requires O(n) extra space. Quick Sort is generally faster in practice due to better cache performance and lower constant factors, but it can degrade to O(n²) in the worst case.
  • Heap Sort: Heap Sort has O(n log n) time complexity and O(1) space complexity, but it is not stable and typically slower than Quick Sort due to more complex memory access patterns.
  • Insertion Sort: Insertion Sort is efficient for small or nearly sorted arrays with O(n) best-case time complexity, but it has O(n²) worst-case time complexity. Quick Sort is much faster for larger arrays.
