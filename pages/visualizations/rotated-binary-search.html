Rotated Binary Search Code

function search(arr, target) {
  let left = 0, right = arr.length - 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    if (arr[mid] === target) return mid;

    if (arr[left] <= arr[mid]) {
      // left half is sorted
      if (arr[left] <= target && target < arr[mid]) right = mid - 1;
      else                                            left  = mid + 1;
    } else {
      // right half is sorted
      if (arr[mid] < target && target <= arr[right])  left  = mid + 1;
      else                                             right = mid - 1;
    }
  }
  return -1;
}

How Search in a Rotated Sorted Array Works

A rotated sorted array (like [4,5,6,7,0,1,2]) isn't sorted end-to-end, so plain binary search's "compare to mid and go left or right" logic breaks — but here's the trick: at least one of the two halves around mid is always fully sorted. Once you know which half that is, you can check in O(1) whether the target could be hiding there.

Step by step

  • Compute mid as usual (gold). If it's the target, done.
  • Compare arr[left] to arr[mid]: if arr[left] <= arr[mid], the left half is sorted (magenta outline); otherwise the right half is.
  • If the sorted half is the left one: check whether the target falls inside [arr[left], arr[mid]). If yes, search left; if no, it must be in the other (unsorted-looking) half — search right.
  • Symmetric logic applies if the right half is the sorted one.
  • Repeat until found or the range is empty.

Why this still works in O(log n)

Every step still throws away one full half of the remaining range — the only difference from plain binary search is a slightly smarter test for "which half could possibly contain the target," using the guaranteed-sorted half as a reference point instead of a single ordering assumption over the whole array.

Complexity

Time: O(log n) — same as standard binary search.
Space: O(1).

When is it used?

  • Searching in a sorted array that's been circularly shifted (e.g. version histories, ring buffers).
  • Finding the rotation point itself (a close cousin of this problem).
  • A good example of adapting binary search's invariant instead of abandoning it.

Compared to plain binary search

  • Rotated search (this): O(log n), needs one extra check per step to identify the sorted half.
  • Plain binary search: O(log n), assumes the entire array is sorted from the start.
  • Linear search fallback: O(n) — always correct regardless of rotation, but loses the logarithmic speedup entirely.
