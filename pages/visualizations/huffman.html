Greedy Code

function huffman(freqs) {
  // freqs: [{ char, freq }]
  let queue = freqs.map(f => ({ ...f, left: null, right: null }));

  while (queue.length > 1) {
    // Greedy: always merge the two least-frequent nodes
    queue.sort((a, b) => a.freq - b.freq);
    const a = queue.shift();
    const b = queue.shift();

    const merged = {
      char: null,
      freq: a.freq + b.freq,
      left: a,
      right: b
    };
    queue.push(merged);
  }

  return queue[0]; // root of the Huffman tree
}

// Walk the tree: left = '0', right = '1', to get each char's code

How Huffman Coding Works

Huffman coding builds a variable-length binary code for a set of characters so that more frequent characters get shorter codes — minimizing the total encoded length. It's a greedy algorithm built entirely around a priority queue: repeatedly combine the two least-frequent items into one.

Step by step

  • Put every character in a priority queue, keyed by frequency.
  • Repeatedly remove the two smallest frequency nodes (yellow).
  • Merge them into a new internal node whose frequency is their sum — mark it merged (green) and push it back into the queue.
  • Repeat until only one node remains — that's the root of the Huffman tree.
  • Walk the tree from the root: each left branch appends a 0, each right branch appends a 1. The bit string collected at each leaf is that character's code.

Why merge the two smallest first?

Every merge pushes both nodes one level deeper in the final tree, adding one bit to their eventual codes. Choosing the two least-frequent nodes to go deeper (rather than more frequent ones) minimizes the total weighted code length — an exchange argument again shows any other choice can only be as good or worse.

Complexity

Time: O(n log n) — n-1 merges, each needing an O(log n) priority-queue operation.
Space: O(n) for the tree and the resulting code table.

When is it used?

  • Lossless file compression (the basis of DEFLATE, used in gzip, PNG, and ZIP).
  • JPEG and MP3 use Huffman coding as one stage of their compression pipelines.
  • Any scenario needing an optimal prefix-free binary code.

Compared to other approaches

  • Huffman (this): greedy priority-queue merges — provably optimal prefix code for known, static frequencies.
  • Fixed-length coding: simpler, but wastes bits on frequent characters that could use shorter codes.
  • Arithmetic coding: can beat Huffman's compression ratio (it isn't restricted to whole-bit codes per symbol), but is more complex to implement and decode.
