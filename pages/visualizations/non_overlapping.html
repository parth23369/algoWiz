Greedy Code

function eraseOverlapIntervals(intervals) {
  if (intervals.length === 0) return 0;

  // Greedy: sort by end time
  intervals.sort((a, b) => a[1] - b[1]);

  let prevEnd  = -Infinity;
  let removed  = 0;

  for (const [start, end] of intervals) {
    if (start < prevEnd) {
      // overlaps previous kept interval
      removed++;
    } else {
      // no overlap, keep it
      prevEnd = end;
    }
  }

  return removed;
}

Given a set of intervals, this problem asks for the minimum number that must be removed so the rest don't overlap. It's a classic greedy-algorithm problem (LeetCode 435) — the trick is choosing which interval to sort by.

Step by step

  • Sort all intervals by their end time (ascending).
  • Track a prevEnd boundary, starting at -∞ (shown as the dashed magenta line).
  • Mark each interval, in sorted order, as currently visiting (yellow).
  • If its start is before prevEnd, it overlaps — mark it removed (red) and don't move the boundary.
  • Otherwise it fits — mark it kept (green) and advance prevEnd to this interval's end.
  • The final removed count is the minimum number of intervals to erase.

Why sort by end time?

Sorting by end time is what makes this greedy — keeping the interval that finishes earliest always leaves the most room for future intervals, so a locally-greedy choice never costs you the globally optimal answer (an exchange-argument proof).

Complexity

Time: O(n log n) — dominated by the sort; the scan afterward is O(n).
Space: O(1) extra (O(n) if the sort isn't in-place).

When is it used?

  • Meeting room / activity scheduling problems.
  • Resource allocation with time slots.
  • Minimum platforms/rooms needed for events.
  • Job sequencing with deadlines.

Compared to other approaches

  • Greedy (this): O(n log n) — sort by end, single pass; optimal for this problem.
  • Sort by start: doesn't work directly — a long early interval can block many later ones, giving a suboptimal count.
  • Dynamic Programming: O(n log n) or O(n²) — finds the longest chain of non-overlapping intervals directly; more general but unnecessary overhead here since greedy is already optimal.
