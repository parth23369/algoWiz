Backtracking Code

function solveMaze(grid, n) {
  const path = [];
  const visited = Array.from({length:n}, () => new Array(n).fill(false));
  const moves = [[1,0],[0,1],[-1,0],[0,-1]]; // down, right, up, left

  function backtrack(r, c) {
    if (r < 0 || c < 0 || r >= n || c >= n) return false;
    if (grid[r][c] === 0 || visited[r][c]) return false;   // wall or seen

    visited[r][c] = true;
    path.push([r, c]);

    if (r === n-1 && c === n-1) return true;   // reached destination

    for (const [dr, dc] of moves) {
      if (backtrack(r + dr, c + dc)) return true;
    }

    path.pop();          // undo — this cell leads to a dead end
    visited[r][c] = false;
    return false;
  }

  return backtrack(0, 0) ? path : null;
}

How Rat in a Maze Works

A rat starts at the top-left of a maze and needs to reach the bottom-right, moving only through open cells. Backtracking explores move by move, extending a path as far as it can — and the instant it hits a dead end, it retraces its steps and tries a different direction from the last cell that still had options.

Step by step

  • From the current cell, mark it visited and add it to the path (gold while being tried).
  • If this is the destination, success — the path is complete.
  • Otherwise, try each direction in order (down, right, up, left): recurse into any open, unvisited neighbor.
  • If a recursive call succeeds, the answer propagates back up immediately — no further options need to be tried.
  • If none of the neighbors lead anywhere, this cell is a dead end (red) — remove it from the path, unmark it as visited, and backtrack to whichever cell called it.

Why unmark on backtrack?

Un-visiting a dead-end cell (rather than leaving it permanently marked) matters when a cell could be legitimately reached again via a completely different path later — although for maze-with-single-path problems, once a full search from a cell fails, it truly can never help, so some implementations skip the un-mark as an optimization.

Complexity

Time: O(4^(n²)) in the absolute worst case (branching in up to 4 directions per cell), though visited-tracking prunes this drastically in practice — real mazes resolve far faster.
Space: O(n²) for the visited grid and recursion stack.

When is it used?

  • Pathfinding in grid-based puzzles and games.
  • Robot motion planning in constrained environments.
  • Foundational example for more advanced pathfinding (BFS/A* are typically faster when only the shortest path matters).

Compared to other pathfinding approaches

  • Backtracking (this): finds a valid path, not necessarily the shortest one; simple to reason about and implement.
  • BFS: guarantees the shortest path in an unweighted grid, exploring level by level instead of diving down one path at a time.
  • A*: like BFS/Dijkstra but guided by a heuristic — usually much faster when a good distance estimate to the goal is available.
