Greedy Code

function fractionalKnapsack(items, capacity) {
  // Greedy: sort by value/weight ratio, descending
  items.sort((a, b) => (b.value / b.weight) - (a.value / a.weight));

  let remaining = capacity;
  let totalValue = 0;

  for (const item of items) {
    if (remaining <= 0) break;

    if (item.weight <= remaining) {
      totalValue += item.value;       // take it whole
      remaining  -= item.weight;
    } else {
      const fraction = remaining / item.weight;
      totalValue += item.value * fraction;  // take a fraction
      remaining = 0;
    }
  }

  return totalValue;
}

Unlike 0/1 Knapsack, items here can be split — you can take half a sack of rice. That single relaxation is what lets a greedy strategy work perfectly: always take as much as possible of whichever item gives the most value per unit of weight.

Step by step

  • Compute each item's value/weight ratio and sort items by it, descending.
  • Walk through items in that order, marking each currently visiting (yellow).
  • If the whole item fits in remaining capacity, take it entirely — mark full (green), reduce remaining capacity.
  • If only part of it fits, take that fraction — mark partial (magenta), and remaining capacity drops to 0.
  • Once capacity hits 0, every later item is left behind (red).

Why sort by ratio?

Filling the sack with the highest-ratio item first always maximizes value per unit of space used — an exchange argument shows that swapping any fraction of a lower-ratio item in for a higher-ratio one never decreases total value, so the locally greedy order is also globally optimal.

Complexity

Time: O(n log n) — dominated by the sort.
Space: O(1) extra beyond the sort.

When is it used?

  • Resource allocation where partial amounts are usable (liquids, currency, raw materials).
  • Bandwidth or budget splitting across divisible tasks.
  • Teaching contrast piece for 0/1 Knapsack — same setup, different constraint, completely different algorithm class.

Compared to 0/1 Knapsack

  • Fractional (this): items divisible — greedy by ratio is always optimal, O(n log n).
  • 0/1 Knapsack: items indivisible — greedy by ratio can fail; needs O(n·W) DP for a guaranteed optimum.
