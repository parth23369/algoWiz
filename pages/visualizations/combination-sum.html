Backtracking Code

function combinationSum(candidates, target) {
  const results = [];
  const current = [];

  function backtrack(start, remaining) {
    if (remaining === 0) {
      results.push([...current]);
      return;
    }
    if (remaining < 0) return;   // overshot — prune this branch

    for (let i = start; i < candidates.length; i++) {
      current.push(candidates[i]);

      // pass i (not i+1): the same candidate can be reused
      backtrack(i, remaining - candidates[i]);

      current.pop();            // undo — backtrack
    }
  }

  backtrack(0, target);
  return results;
}

How Combination Sum Backtracking Works

Given a set of candidate numbers (each reusable any number of times) and a target, find every combination that adds up exactly to it. This backtracking search adds candidates one at a time, and the moment the running sum can't possibly reach the target validly, it prunes that entire branch instead of continuing uselessly.

Step by step

  • Track the current combination and how much of the target is still remaining.
  • If remaining hits exactly 0, the current combination is a valid answer — record it.
  • If remaining goes negative, this branch overshot — stop immediately (pruned, no further recursion wasted).
  • Otherwise, try each candidate from the current start index onward (gold): add it to the combination, subtract its value from remaining, and recurse — passing the same start index, since repetition is allowed.
  • After that recursive branch fully returns, undo: remove the candidate and try the next one instead.

Why "start index," not "used" flags?

Passing the same index forward (rather than 0) allows a candidate to be reused, while only ever moving the start index forward (never backward) guarantees each combination is generated in one canonical non-decreasing order — preventing the same combination from being counted twice in a different arrangement.

Complexity

Time: exponential in the worst case — roughly O(target/min(candidates)) branching depth, pruned heavily whenever the sum exceeds target early.
Space: O(target / min(candidates)) for the recursion depth.

When is it used?

  • Making change with unlimited coin supply.
  • Any "which combination of reusable items reaches an exact total" problem.
  • Constraint-based configuration search with a numeric budget.

Compared to other backtracking shapes

  • Combination Sum (this): elements can repeat, and pruning on remaining < 0 cuts off entire invalid subtrees early.
  • Subsets: a similar include/exclude idea, but no repetition and no target-based pruning — every leaf of the decision tree is a valid answer.
  • Permutations: order matters and every element is used exactly once — a fundamentally different constraint than "reach a sum."
