Radix Sort Code (LSD)

function radixSort(arr) {
  const maxVal = Math.max(...arr);

  for (let exp = 1; Math.floor(maxVal / exp) > 0; exp *= 10) {
    arr = countingSortByDigit(arr, exp);
  }
  return arr;
}

function countingSortByDigit(arr, exp) {
  const buckets = Array.from({length: 10}, () => []);

  for (const num of arr) {
    const digit = Math.floor(num / exp) % 10;
    buckets[digit].push(num);      // stable: append, keep relative order
  }

  return [].concat(...buckets);    // flatten buckets 0 → 9 back into one array
}

How Radix Sort Works

Sitting in its bucket

Radix sort sorts numbers digit by digit instead of comparing whole numbers to each other. The LSD (least significant digit) variant shown here processes the ones digit first, then tens, then hundreds — and as long as each pass is stable, the array ends up fully sorted once every digit has been processed.

Step by step

  • Find the maximum number to know how many digit-passes are needed.
  • For the current digit place (ones, tens, hundreds, …), compute each number's digit there: Math.floor(num / exp) % 10.
  • Drop each number into the bucket matching that digit (gold while being placed, green once bucketed) — buckets 0 through 9.
  • Crucially, process numbers in their current array order when filling buckets — this is what keeps the sort stable.
  • Concatenate the buckets back together in order 0 → 9; this becomes the new array order.
  • Move to the next digit place and repeat, until the digit place exceeds the largest number.

Why does sorting by ones-then-tens-then-hundreds work?

Because each pass is stable, numbers that tie on a more significant digit retain whatever relative order was established by the earlier (less significant) passes — so by the time the most significant digit is processed, the whole number is correctly ordered.

Complexity

Time: O(d · (n + k)) — d digit passes, each an O(n + k) counting sort (k = 10 for base-10 buckets).
Space: O(n + k) for the buckets.
Stable: Yes — required for correctness, not just a nice property.

When is it used?

Great for sorting large sets of fixed-width integers (or strings) — like sorting 32-bit integers, phone numbers, or dates — where the number of digits is small and bounded compared to n.

Compared to other sorts

  • Radix Sort: O(d·(n+k)) — can beat O(n log n) comparison sorts when d is small, but doesn't generalize to arbitrary comparable data.
  • Counting Sort: what each digit-pass of radix sort actually is, applied once to the whole value range instead of digit-by-digit.
  • Merge/Quick Sort: comparison-based and fully general, but bounded below by O(n log n) — radix sort sidesteps that bound entirely by never comparing whole values.
