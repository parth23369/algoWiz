Backtracking Code

function permute(arr) {
  const results = [];
  const current = [];
  const used = new Array(arr.length).fill(false);

  function backtrack() {
    if (current.length === arr.length) {
      results.push([...current]);
      return;
    }

    for (let i = 0; i < arr.length; i++) {
      if (used[i]) continue;         // already placed — skip

      used[i] = true;
      current.push(arr[i]);

      backtrack();                   // recurse with one more element placed

      current.pop();                 // undo — backtrack
      used[i] = false;
    }
  }

  backtrack();
  return results;
}

How Permutation Backtracking Works

Generating all permutations of a set means trying every possible ordering. Backtracking builds one ordering at a time, slot by slot: pick any unused element for the next slot, recurse to fill the rest, then undo that choice and try a different element — systematically covering every arrangement without ever repeating one.

Step by step

  • Maintain a current partial permutation and a used flag per element.
  • If the current permutation is already full length, record it as a complete result.
  • Otherwise, try each unused element (gold) as the next slot.
  • Mark it used, append it to current (green), and recurse to fill the remaining slots.
  • After the recursive call returns (every completion starting with that choice has been found), undo: remove it from current and mark it unused again — freeing it up for a different position in a different branch.

Why "undo" matters here

Without un-marking an element as unused after backtracking, later branches would incorrectly think it's permanently placed and skip using it in other valid orderings — the undo step is exactly what lets the same element appear in every position across different permutations.

Complexity

Time: O(n · n!) — n! permutations, each taking O(n) to construct/copy.
Space: O(n) for the recursion stack and the current partial permutation (not counting the output).

When is it used?

  • Generating all orderings for brute-force search (e.g. small Traveling Salesman instances).
  • Anagram and password/combination generation.
  • Testing every possible sequence of operations in a fixed set.

Compared to other backtracking shapes

  • Permutations (this): every element must appear exactly once, order matters — the "used" set prevents repeats within one arrangement.
  • Subsets: each element gets an independent include/exclude decision, and order doesn't matter — no "used" tracking needed, just an index that moves strictly forward.
  • Combination Sum: elements can repeat, but choices only move forward through a start index to avoid generating the same combination twice.
