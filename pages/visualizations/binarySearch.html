Binary Search Code

function binarySearch(arr, target) {
  let left = 0, right = arr.length - 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);

    if (arr[mid] === target) return mid;

    if (arr[mid] < target) left  = mid + 1;
    else                    right = mid - 1;
  }

  return -1;  // not found
}

Binary search finds a target in a sorted array by repeatedly checking the middle element and throwing away the half that can't contain the target — cutting the search space in half every step instead of scanning one element at a time.

Step by step

  • Track a left and right boundary, initially the whole array.
  • Compute mid — the middle index between them (gold).
  • If arr[mid] === target, done — found it (green).
  • If arr[mid] < target, the target must be to the right — move left to mid + 1.
  • Otherwise it must be to the left — move right to mid - 1.
  • Everything outside [left, right] is now provably irrelevant (dimmed) and never checked again.
  • Stop when found, or when left > right (target isn't present).

Why the array must be sorted

The whole trick relies on being able to tell which half the target is in just from one comparison. That only works if the array is ordered — on an unsorted array, ruling out half based on a single comparison would be unsound.

Complexity

Time: O(log n) — the search space halves every step.
Space: O(1) iteratively, or O(log n) if implemented recursively (call stack).

When is it used?

  • Looking up values in any sorted array, index, or dictionary.
  • Database index lookups (B-trees generalize this idea).
  • The foundation for binary-search-on-answer-space and rotated-array variants.

Compared to other search strategies

  • Binary search (this): O(log n), but requires sorted data.
  • Linear search: O(n) — works on unsorted data, but far slower on large inputs.
  • Jump search: O(√n) — a middle ground, useful when random access is costly (e.g. linked structures).
