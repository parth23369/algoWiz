Greedy Code

function greedyCoinChange(coins, amount) {
  // Greedy: always use the largest coin that fits
  coins.sort((a, b) => b - a);

  const used = [];
  let remaining = amount;

  for (const coin of coins) {
    while (coin <= remaining) {
      used.push(coin);
      remaining -= coin;
    }
  }

  // remaining === 0 only if a solution using these coins exists
  return remaining === 0 ? used : null;
}

How Greedy Coin Change Works (and When It Breaks)

Coin being tried
Coin used

The idea is simple: always hand over the largest coin that doesn't overshoot the remaining amount. For everyday currency systems (like 1, 5, 10, 25) this greedy approach happens to give the fewest coins possible — but it isn't guaranteed to work for every set of denominations, which makes this a great case study in greedy's limits.

Step by step

  • Sort the coins largest to smallest.
  • Repeatedly take the largest coin that's still ≤ the remaining amount.
  • Subtract it from the remaining amount and record the pick (green).
  • Continue until the remaining amount hits exactly 0 (success), or no coin fits anymore while remaining > 0 (greedy has failed to find a solution, even if one exists).

Where greedy silently breaks

With coins {1, 3, 4} and amount 6, greedy picks 4, then 1, then 1 — three coins. But 3 + 3 only needs two. Greedy isn't wrong about being fast, it's wrong about being optimal: it commits to the biggest coin immediately and never reconsiders, so it can't see that giving up a bit of "greed" now pays off later. Complexity

Time: O(n log n + amount/smallest coin) — sort once, then a bounded number of coin picks.
Space: O(1) beyond the output list.

When is it safe to use?

  • "Canonical" coin systems (like most real-world currencies) where greedy is provably optimal.
  • Making change quickly when you already know the coin system is canonical.

Compared to Dynamic Programming

  • Greedy (this): very fast, but only correct for specific ("canonical") coin sets — and it won't warn you when it's wrong.
  • DP (Coin Change, LeetCode 322): O(amount · n) time, always correct for any coin set — builds up dp[amount] = min coins for exactly that amount by trying every coin at every amount, rather than committing greedily.
