Counting Sort Code

function countingSort(arr, maxVal) {
  const count = new Array(maxVal + 1).fill(0);
  for (const v of arr) count[v]++;          // tally occurrences

  for (let i = 1; i <= maxVal; i++) {
    count[i] += count[i - 1];                // prefix sum = final position
  }

  const output = new Array(arr.length);
  for (let i = arr.length - 1; i >= 0; i--) { // iterate backward for stability
    output[count[arr[i]] - 1] = arr[i];
    count[arr[i]]--;
  }

  return output;
}

How Counting Sort Works

Counting sort doesn't compare elements at all — it counts how many times each value appears, then uses those counts to figure out exactly where each element belongs. That only works when values fall in a small, known range, but when they do, it's faster than any comparison sort could ever be.

Step by step

  • Count: scan the input once, incrementing count[value] for every element (gold cell lights up).
  • Prefix sum: transform the count array so count[v] now means "how many elements are ≤ v" — this directly gives the final index range for each value.
  • Place: walk the input from the end backward (this preserves stability), and for each element, place it at position count[value] - 1 in the output, then decrement that count.
  • Once every element has been placed, the output array is fully sorted.

Why walk backward when placing?

Placing elements in reverse input order means that if two elements have equal value, the one that appeared earlier in the input still ends up earlier in the output — preserving their original relative order, which is what makes counting sort stable.

Complexity

Time: O(n + k) — n elements to count/place, k = range of possible values.
Space: O(n + k) for the count array and output array.
Stable: Yes, when implemented with the backward placement pass shown here.

When is it used?

Excellent when the value range k is small relative to n (e.g. sorting exam scores 0-100, or single-digit values). It's also the core subroutine used inside radix sort to sort by each individual digit.

Compared to other sorts

  • Counting Sort: O(n + k) — beats comparison sorts' O(n log n) floor, but only works well when k is small.
  • Radix Sort: applies counting sort digit-by-digit, extending this idea to numbers with a large range but a bounded number of digits.
  • Merge/Quick Sort: O(n log n) — comparison-based, so they work on any orderable data type, not just small-range integers.
