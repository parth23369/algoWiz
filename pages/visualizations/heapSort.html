Heap Sort Code

function heapSort(arr) {
  const n = arr.length;

  // Build a max heap
  for (let i = Math.floor(n/2) - 1; i >= 0; i--) {
    heapify(arr, n, i);
  }

  // Repeatedly move the max to the end, shrink the heap
  for (let end = n - 1; end > 0; end--) {
    [arr[0], arr[end]] = [arr[end], arr[0]];
    heapify(arr, end, 0);
  }
  return arr;
}

function heapify(arr, heapSize, root) {
  let largest = root;
  const left  = 2*root + 1, right = 2*root + 2;

  if (left  < heapSize && arr[left]  > arr[largest]) largest = left;
  if (right < heapSize && arr[right] > arr[largest]) largest = right;

  if (largest !== root) {
    [arr[root], arr[largest]] = [arr[largest], arr[root]];
    heapify(arr, heapSize, largest);   // sift down
  }
}

Heap sort treats the array as a binary tree stored implicitly in a flat list, where each parent's children live at indices 2i+1 and 2i+2. First it rearranges the array into a max heap (every parent ≥ its children), then repeatedly pulls the maximum (always at the root) out to the end.

Step by step

  • Build the heap: starting from the last non-leaf node and working backward to the root, heapify each subtree — compare a node to its children (yellow) and swap down (red) if a child is bigger, repeating until that subtree satisfies the max-heap property.
  • Extract the max: the largest element is always at index 0. Swap it with the last element of the current heap (red), which places it in its final sorted spot (green).
  • Shrink and re-heapify: reduce the heap size by one (dimming that final element out of the heap) and heapify from the root again to restore the max-heap property.
  • Repeat extraction until the heap is empty — one element at a time, always sorted.

Complexity

Time: O(n log n) — building the heap is O(n), and each of the n extractions costs O(log n) to re-heapify.
Space: O(1) — sorts in place, no extra array needed (unlike merge sort).
Stable: No — swaps during heapify can reorder equal elements.

When is it used?

Guarantees O(n log n) even in the worst case (unlike quicksort, which can degrade to O(n²)), while using no extra memory (unlike merge sort). A solid choice when worst-case time guarantees and memory constraints both matter.

Compared to other sorts

  • Heap Sort: O(n log n) guaranteed, O(1) space — not stable, and typically slower in practice than quicksort due to poor cache locality.
  • Quick Sort: O(n log n) average but O(n²) worst case — usually faster in practice, in-place, not stable.
  • Merge Sort: O(n log n) guaranteed like heap sort, and stable — but needs O(n) extra space where heap sort needs none.
