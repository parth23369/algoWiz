Buy & Sell Stocks (State Machine)

price[i]
cash[i] = max profit, holding no stock
hold[i] = max profit, currently holding stock
Press "New Prices" to start
Slow Fast

State Machine DP Code

function maxProfit(prices) {
  const n = prices.length;
  let cash = 0;          // not holding a stock
  let hold = -prices[0]; // holding a stock

  for (let i = 1; i < n; i++) {
    const prevCash = cash;
    // sell today, or stay in cash
    cash = Math.max(cash, hold + prices[i]);
    // buy today, or keep holding
    hold = Math.max(hold, prevCash - prices[i]);
  }

  return cash;  // best to end without holding
}

How Buy & Sell Stocks Works

Today (i)
Sold today (cash increased)
Bought today (hold improved)

With unlimited transactions allowed (buy, sell, buy again, as many times as you like — one share at a time), the greedy "buy every local dip, sell every local peak" idea actually works, but the DP version generalizes cleanly to variants with fees or cooldowns. It's a state machine DP: on any day you're in exactly one of two states — holding a stock, or not.

Step by step

  • Track two rolling values per day: cash[i] (best profit if you own no stock) and hold[i] (best profit if you're currently holding one).
  • Base case: cash[0] = 0, hold[0] = -price[0] (buying on day 0 costs its price).
  • Each day, cash[i] is either yesterday's cash (do nothing) or selling today: hold[i-1] + price[i].
  • hold[i] is either yesterday's hold (do nothing) or buying today: cash[i-1] - price[i].
  • The answer is cash[n-1] — you should never end holding a stock you haven't sold.

Recurrence

cash[i] = max( cash[i-1], hold[i-1] + price[i] )
hold[i] = max( hold[i-1], cash[i-1] - price[i] )

Complexity

Time: O(n) — one pass, two O(1) updates per day.
Space: O(1) if you only keep yesterday's cash and hold (as shown), or O(n) if you keep the full history for visualization/backtracking.

When is it used?

  • Any repeated buy/sell trading simulation.
  • Variants add a transaction fee, a cooldown day after selling, or a cap on the number of transactions — each just adds more states to the machine.
  • General template for "which state am I in today" DP problems (e.g. game-turn DP).

Compared to other DP shapes

  • State machine DP (this): a small fixed set of states per step, transitions between them — O(n · states).
  • 1D DP (House Robber): single state per index, no branching between multiple "modes."
  • Greedy: for the unlimited-transaction case, simply summing every positive day-to-day price increase gives the same answer with O(1) space — but this stops working once fees or transaction limits are added, which is exactly where the DP formulation pays off.
