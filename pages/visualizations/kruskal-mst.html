Kruskal's Algorithm Code

function kruskal(edges, n) {
  edges.sort((a, b) => a.weight - b.weight);

  const parent = Array.from({length: n}, (_, i) => i);
  function find(x) { return parent[x] === x ? x : (parent[x] = find(parent[x])); }
  function union(a, b) { parent[find(a)] = find(b); }

  const mst = [];
  let totalWeight = 0;

  for (const edge of edges) {
    if (find(edge.u) !== find(edge.v)) {
      union(edge.u, edge.v);   // merge the two components
      mst.push(edge);
      totalWeight += edge.weight;
    }
    // else: would form a cycle — reject
  }

  return { mst, totalWeight };
}

How Kruskal's Algorithm Works

Rather than growing one tree outward like Prim's, Kruskal's algorithm looks at the whole edge list at once: sort every edge by weight, then greedily accept each one as long as it doesn't connect two nodes that are already connected (which would create a cycle).

Step by step

  • Sort all edges by weight, ascending.
  • Track which "component" each node currently belongs to, using a union-find (disjoint-set) structure.
  • For each edge in sorted order (gold), check whether its two endpoints are already in the same component.
  • If they're in different components, accept the edge (green) and merge the components.
  • If they're already in the same component, reject it (red) — adding it would create a cycle, which a tree can't have.
  • Stop once n-1 edges have been accepted (all nodes are in one component).

Why does the cheapest-first order work?

By the same cut-property that justifies Prim's algorithm: whenever an edge is the lightest one connecting two currently-separate components, some minimum spanning tree must include it — so accepting it can never make the final result worse.

Complexity

Time: O(E log E) — dominated by sorting the edges; union-find operations are nearly O(1) amortized (with path compression and union by rank).
Space: O(V) for the union-find structure.

When is it used?

  • Network design when the full edge list is available up front and the graph is sparse.
  • Clustering — stopping Kruskal's early (before merging into a single tree) is a classic way to build k clusters.
  • Circuit design and any minimum-cost connectivity problem.

Compared to Prim's Algorithm

  • Kruskal's (this): globally sorts edges once, uses union-find to avoid cycles — O(E log E), well-suited to sparse graphs.
  • Prim's: grows a single connected tree from a starting node using a priority queue — O(E log V), often faster on dense graphs.
  • Both are greedy, and both are guaranteed to find a correct minimum spanning tree — they differ only in exploration order and data structures.
