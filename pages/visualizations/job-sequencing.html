Greedy Code

function jobSequencing(jobs) {
  // Greedy: sort by profit, descending
  jobs.sort((a, b) => b.profit - a.profit);

  const maxDeadline = Math.max(...jobs.map(j => j.deadline));
  const slots = new Array(maxDeadline + 1).fill(null);
  let totalProfit = 0;

  for (const job of jobs) {
    // try the latest free slot at or before this job's deadline
    for (let t = Math.min(maxDeadline, job.deadline); t >= 1; t--) {
      if (slots[t] === null) {
        slots[t] = job.id;
        totalProfit += job.profit;
        break;
      }
    }
  }

  return { slots, totalProfit };
}

How Job Sequencing Works

Each job takes exactly one unit of time and earns a profit only if completed by its deadline. You want to pick and schedule jobs to maximize total profit, and only one job can occupy any given time slot. The greedy trick: always consider the most profitable job first, and give it the latest possible slot it can still make.

Step by step

  • Sort all jobs by profit, descending.
  • For each job (most profitable first), scan backward from its deadline toward slot 1, looking for a free slot.
  • If a free slot is found, assign the job there — mark scheduled (green).
  • If every slot up to its deadline is already taken, the job can't be completed in time — mark rejected (red).
  • Total profit is the sum of all scheduled jobs' profits.

Why the latest free slot?

Placing a job as late as possible (rather than as early as possible) preserves earlier, more flexible slots for other jobs with tighter deadlines — an exchange argument shows this never costs you profit and can only help fit in more jobs.

Complexity

Time: O(n log n + n·d) — sorting plus, for each job, scanning up to d slots (d = max deadline). A disjoint-set/union-find version brings the slot search down to near O(n α(n)).
Space: O(d) for the slot array.

When is it used?

  • Single-machine scheduling with deadlines and profits/penalties.
  • Task prioritization systems where late completion earns nothing.
  • Foundational example for weighted interval scheduling variants.

Compared to other approaches

  • Greedy (this): sort by profit, always take the latest available slot — optimal and efficient.
  • Sort by deadline instead: doesn't maximize profit directly — you'd need extra bookkeeping (e.g. a min-heap of scheduled profits to evict later) to match the profit-first greedy's guarantee.
  • Brute force: O(2ⁿ) — tries every subset of jobs and every valid ordering; infeasible beyond small n.
