DP Code (Tabulation)

function knapsack(weights, values, W) {
  const n  = weights.length;
  const dp = Array.from({ length: n + 1 },
              () => new Array(W + 1).fill(0));

  for (let i = 1; i <= n; i++) {
    for (let w = 0; w <= W; w++) {
      if (weights[i - 1] <= w) {
        dp[i][w] = Math.max(
          dp[i - 1][w],                       // exclude item
          values[i - 1] + dp[i - 1][w - weights[i - 1]]  // include
        );
      } else {
        dp[i][w] = dp[i - 1][w];              // can't fit
      }
    }
  }

  return dp[n][W];
}

On the optimal path

Given items with weights and values, and a knapsack of fixed capacity, the 0/1 Knapsack problem asks for the maximum value achievable — where each item can either be taken whole or left behind, never split. That "whole or nothing" rule is exactly why greedy strategies fail here and a full DP table is needed.

Step by step

  • Build a table dp[i][w] — best value using the first i items with capacity w.
  • Row 0 and column 0 start at 0 (no items, or no capacity, means no value).
  • For each cell, mark it currently computing (yellow).
  • If the current item's weight fits (<= w), compare excluding it (dp[i-1][w]) against including it (value + dp[i-1][w-weight]), and keep the larger.
  • If it doesn't fit, just carry down dp[i-1][w] — mark it filled (cyan).
  • Once the table is full, backtrack from the bottom-right corner to recover which items were actually chosen — those cells are marked green.

Recurrence

dp[i][w] = max( dp[i-1][w], value[i] + dp[i-1][w - weight[i]] )  if weight[i] ≤ w,
else dp[i][w] = dp[i-1][w].

Complexity

Time: O(n · W) — one computation per table cell.
Space: O(n · W) for the full table, or O(W) if only the previous row is kept (space-optimized, though then the item-selection backtrack needs extra bookkeeping).

When is it used?

  • Budget allocation with indivisible options.
  • Cargo loading and resource packing problems.
  • Project/portfolio selection under a fixed budget.
  • Subset-sum and partition-style problems (special cases of knapsack).

Compared to other approaches

  • Greedy (value/weight ratio): works for the fractional knapsack, but is not guaranteed optimal here since items can't be split.
  • Brute force / recursion: O(2ⁿ) — tries every subset; DP avoids recomputing overlapping subproblems.
  • Memoization (top-down): same O(n·W) complexity as tabulation, but only computes the subproblems actually reached from (n, W).
