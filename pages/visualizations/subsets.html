Backtracking Code

function subsets(arr) {
  const results = [];
  const current = [];

  function backtrack(index) {
    if (index === arr.length) {
      results.push([...current]);   // every index decided — record it
      return;
    }

    // Choice 1: include arr[index]
    current.push(arr[index]);
    backtrack(index + 1);
    current.pop();                  // undo — backtrack

    // Choice 2: exclude arr[index]
    backtrack(index + 1);
  }

  backtrack(0);
  return results;
}

How Subsets Backtracking Works

The power set of a set with n elements has 2ⁿ subsets — every element is either in or out. Backtracking generates all of them by making that include/exclude decision one element at a time, and exploring both branches for every decision rather than picking just one.

Step by step

  • Move through elements by index, left to right (gold = currently deciding).
  • Once every index has been decided (index reaches the end), the current partial subset is complete — record it.
  • Branch 1 — include: add this element to the current subset (green), recurse to decide the next index, then remove it again (undo) once that branch is fully explored.
  • Branch 2 — exclude: simply recurse to the next index without adding anything (dimmed).
  • Because both branches are tried for every element, all 2ⁿ combinations get generated exactly once.

Why this naturally produces every subset

Each of the n elements independently doubles the number of possibilities — for element 1, both "in" and "out" are explored; for each of those, element 2 again splits into two, and so on. That's exactly 2ⁿ leaves in the decision tree, one for each possible subset.

Complexity

Time: O(n · 2ⁿ) — 2ⁿ subsets, each up to O(n) to copy into the results.
Space: O(n) for the recursion stack and current subset (excluding the output).

When is it used?

  • Enumerating all possible feature/option combinations.
  • Brute-force search over subset-based problems (subset sum, partitioning).
  • Building truth tables for boolean expressions.

Compared to other backtracking shapes

  • Subsets (this): one independent include/exclude decision per index — order doesn't matter, no "used" tracking.
  • Permutations: every element must appear exactly once, but order matters — needs a "used" set instead of an index that only moves forward.
  • Combination Sum: like subsets, but elements can be reused and the branching is pruned early once the running sum exceeds the target.
