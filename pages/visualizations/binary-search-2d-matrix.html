2D Matrix Binary Search Code

function searchMatrix(matrix, target) {
  const rows = matrix.length, cols = matrix[0].length;
  let lo = 0, hi = rows * cols - 1;

  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    const row = Math.floor(mid / cols);
    const col = mid % cols;
    const val = matrix[row][col];

    if (val === target) return [row, col];

    if (val < target) lo = mid + 1;
    else               hi = mid - 1;
  }

  return null;  // not found
}

This works on a matrix where each row is sorted left to right, and the first element of every row is greater than the last element of the row above it. That property means the whole matrix, read row by row, is really just a flattened sorted array — so plain binary search still applies, with one extra step to translate a linear index back into a (row, column) pair.

Step by step

  • Treat the matrix as a single sorted array of length rows × cols, indexed 0 to rows·cols - 1.
  • Binary search that virtual index range exactly like 1D binary search: compute mid (gold).
  • Convert mid to real coordinates: row = Math.floor(mid / cols), col = mid % cols.
  • Compare matrix[row][col] to the target and eliminate half the range, same as before.
  • Stop when found (green), or when the range is empty.

Why not search row-by-row?

Because the matrix is sorted globally (not just within each row), there's no need to narrow down which row first and then binary search within it — one binary search over the flattened index range does the whole job in a single O(log(rows·cols)) pass.

Complexity

Time: O(log(rows · cols)) — one binary search over the full flattened matrix.
Space: O(1).

When is it used?

  • Any matrix or 2D table stored with this global sorted property (common in some database index layouts).
  • A stepping stone to other 2D search variants, like matrices sorted independently by row and column (which use a different, staircase-walk approach instead).

Compared to other 2D matrix search variants

  • Fully sorted matrix (this): O(log(rows·cols)) — one binary search, since it's really a 1D sorted array in disguise.
  • Row-wise and column-wise sorted (not globally sorted): can't binary search directly — instead, start from the top-right corner and step left or down each comparison, giving O(rows + cols).
  • Unsorted matrix: no shortcuts — O(rows · cols) brute-force scan.
