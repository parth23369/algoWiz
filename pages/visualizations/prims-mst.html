Prim's Algorithm Code

function prims(graph, start, n) {
  const inMST = new Array(n).fill(false);
  inMST[start] = true;
  let totalWeight = 0;
  let edgesUsed = 0;

  while (edgesUsed < n - 1) {
    // Find the minimum-weight edge connecting MST to non-MST
    let best = { weight: Infinity, u: -1, v: -1 };
    for (let u = 0; u < n; u++) {
      if (!inMST[u]) continue;
      for (const [v, w] of graph[u]) {
        if (!inMST[v] && w < best.weight) {
          best = { weight: w, u, v };
        }
      }
    }

    inMST[best.v] = true;
    totalWeight += best.weight;
    edgesUsed++;
  }

  return totalWeight;
}

A Minimum Spanning Tree (MST) connects every node in a weighted graph using the smallest possible total edge weight, with no cycles. Prim's algorithm builds it by growing a single connected tree one node at a time, always reaching out through the cheapest available edge.

Step by step

  • Start with one node in the MST set (green); everyone else is outside.
  • Look at every edge that crosses the boundary — one endpoint inside the MST, one outside (gold candidates).
  • Pick the minimum-weight such edge, add it to the tree, and pull its outside endpoint into the MST.
  • Repeat until every node has joined — that takes exactly n-1 edges for n nodes.

Why the cheapest crossing edge?

A classic cut-property argument: for any partition of nodes into "in the tree so far" and "not yet," the minimum-weight edge crossing that partition must belong to some minimum spanning tree — so it's always safe to grab it.

Complexity

Time: O(V²) with a simple linear scan for the minimum crossing edge each round (as shown), or O(E log V) with a binary heap.
Space: O(V) for the in-MST set.

When is it used?

  • Network design — laying minimum cable/pipe to connect all sites.
  • Approximation algorithms for harder problems (like the Traveling Salesman Problem).
  • Cluster analysis and image segmentation.

Compared to Kruskal's Algorithm

  • Prim's (this): grows one connected tree from a starting node — efficient on dense graphs with a heap, O(E log V).
  • Kruskal's: sorts all edges once and adds them globally (using union-find to avoid cycles) rather than growing from a single node — often simpler to reason about, and efficient on sparse graphs, O(E log E).
  • Both are greedy and both always produce a correct minimum spanning tree — they just explore the edge set in a different order.
