What is Dynamic Programming?

It is an algorithm, or basically a method, used to optimise the recursive solutions of problems. When we apply the recursive algorithm to a problem then it is highly likely that we will explore all the subproblems of the problem. Now among those subproblems, many are repreated subproblems and thus, we need a mechanism to store the results of those subproblems so that we do not have to recompute them again and again. This is where Dynamic Programming comes into play. It stores the results of the subproblems in a table (or an array) and uses them when needed. Look at the given example of how we use recursive algorithm to solve the Classical problem of Fibonacci Numbers and then later use Dynamic Programming to optimise on the existing solution.

Now this is different from the Greedy algorithm as in Dynamic Programming Problems, you need to specifically go on and explore all the subproblems whereas in Greedy algorithms we are making locally optimal choices before solving any subproblem, hoping that these choices will lead to a globally optimal solution .Back to our discussion, there are different ways to implement Dynamic Programming. The two most common ways are:

1. Top Down Approach (Memoization):
Memoization is a top-bottom recursion based approach that uses a table to store the already computed subproblems. Thus before we procede to compute the next subproblem we check if it is really needed to be computed and stored, next, we check if the result of that subproblem is already present in the table. If it is present then we use that value and do not compute it again. If it is not present then we compute it and store it in the table.
Time complexity of this approach is O(n2) and Space complexity is O(n).

2. Bottom Up Approach (Tabulation):
Tabulation is a bottom up approach that uses the base cases to compute the next subproblem. It then uses a table to store the results of the subproblems and then uses those results to compute the next subproblem. This approach is iterative and does not use recursion. The table is filled in a bottom up manner, starting from the base cases and moving towards the final result. However there are underlying disadvantages to this method, its state transition are difficult to trace and it gets even complicated when a lot of conditions are involved, however it is faster than Memoization because of lack of a recursion call overhead. Every subproblem whether desirable or not need to be computed and filled ONE BY ONE, we can reduce them by applying certain conditions but it outperforms the top-bottom approach by a constant factor.


And there exist a special case of Dynamic Programming when we use some previously computed values to compute the next value. In such cases we can even use a fixed number of variables required to compute the next subproblem to store the values of desired subproblems instead of using a table or an array and then finally return the final subproblem's result. This is called Space Optimisation of Dynamic Programming.

Some popular problems solved using Dynamic Programming are Fibonacci Numbers, Diff Utility (Longest Common Subsequence), Bellman–Ford Shortest Path, Edit Distance and Matrix Chain Multiplication.

We can also ease the task of grasping the concept of Dynamic Programming by studying it as various types of subproblems, like DP on Trees, DP on Graphs, DP on Strings, DP on Bitmasking, DP on Trees and Graphs, DP on Subsets and DP on Paths, DP on Grids, DP on arrays, DP on strings and substrings. Then with further practise you can solve the problems using Dynamic Programming in a more efficient way.
